# PASS/FAIL compliance gate

Pattern [built, ran on real tickets]. This script is a generic rewrite
[built, tested on synthetic data].

## Why

Account-build blocks generated by a chat assistant drifted from the
onboarding runbook a little at a time over about five weeks: dropped
address fields, a name attribute set from the wrong variable, the wrong
casing on the account name, a start-date attribute without its required
prefix. Every block looked right on its own. Once the drift was spotted I
fixed 16 accounts and put a gate in front of the next irreversible step.
The gate runs the same checks the same way every time, no matter which
assistant (or person) wrote the build. On real onboardings later in
September, one run of my gate caught a FAIL row.

## Run it

```powershell
# Local PowerShell 7 (Windows PowerShell 5.1 also works). Read-only. Never connects to a directory.
pwsh -File ./Test-AccountGate.ps1 -SnapshotPath fixtures/snapshot-pass.json     -ExpectedPath fixtures/expected.json
pwsh -File ./Test-AccountGate.ps1 -SnapshotPath fixtures/snapshot-drift.json    -ExpectedPath fixtures/expected.json
pwsh -File ./Test-AccountGate.ps1 -SnapshotPath fixtures/snapshot-accented.json -ExpectedPath fixtures/expected-accented.json
```

The first prints `20 PASS / 0 FAIL` and exits 0. The second prints
`13 PASS / 7 FAIL` and exits 1. The third shows a name with accented
letters passing: the UPN and account name use the base letters, and the
display name keeps the accents. A missing or unreadable file exits 2.

## Use it for real

1. After the build and its read-back, export the account with your own
   read-only command. The script's help shows a `Get-ADUser` example for
   Windows PowerShell 5.1 on a domain controller or RSAT host. Write the
   file as UTF-8 (`Set-Content -Encoding utf8`); the 5.1 default is ANSI,
   which breaks accented names.
2. Write the expected values from the intake to a JSON file shaped like
   `fixtures/expected.json`. Name the attribute your runbook keeps the
   start date in (`StartDateAttribute`) and its prefix (`StartDatePrefix`).
3. Run the gate. If any row FAILs, stop: no directory sync, no ticket
   notes. Fix the FAIL rows and rerun until it is clean.

For a cloud-only account, a `Get-MgUser` export needs a small mapping step
first. Graph uses different names (`jobTitle`, `accountEnabled`,
`onPremisesExtensionAttributes.extensionAttribute10`), the manager comes
back as an object through `-ExpandProperty manager` rather than a DN, and
cloud-only accounts have no account name, OU or DN, so drop those rows
from your copy of the gate.

## Rules it checks

- UPN follows the naming convention and domain
- Account name equals the UPN local part, case-sensitive
- Display name matches the intake, suffix included
- Name (CN) equals the display name
- Given name and surname
- All five office address fields
- Start-date stamp has its prefix and matches the intake
- Department and title (case-sensitive), manager (DN, any case)
- Enabled state
- Created in the right OU
- Member of every required group

Edit the rules to match your own runbook. Keep one row per rule, so a FAIL
points at exactly one thing to fix.
